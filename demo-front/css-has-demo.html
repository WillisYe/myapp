概念与语法速览

`:has()` 是什么？
它让你可以“根据后代/子元素是否存在（或处于某状态）来选择当前元素”。最常见用途：选中父级（以前只能靠 JS）。
记住一句话
把 `E:has(S)` 当成“E 里面存在符合 S 的元素”。其中 S 是一个相对选择器列表，可以包含 `> + ~`、伪类等。
/* 1) 选择“包含某后代”的元素 */ .card:has(.tag.hot) { outline: 2px solid red; } /* 2) 选择“其直接子元素满足条件”的元素 */ .list:has(> li.selected) { border-color: green; } /* 3) 交互联动：父级根据内部 hover/focus 状态改变 */ .menu:has(a:hover) { box-shadow: 0 10px 30px rgba(0,0,0,.12); } /* 4) 表单：只要内部出现无效字段，就整体警告 */ form:has(:invalid) { border-color: orange; } /* 5) 渐进增强（推荐） */ @supports selector(:has(*)) { /* 把 :has() 相关样式包在 supports 里 */ }
你的浏览器似乎不支持 `:has()`
本页仍会展示结构与代码，但“父级跟随子级状态变化”的视觉效果可能看不到。建议换 Chrome / Edge / Safari 新版本，或看下方“降级方案”。

示例 1：表单整体验证（`:has(:invalid)` / `:has(:valid)`）

不写 JS：当表单内部出现无效输入时，外层卡片整体变“警告”；当全部有效时变“通过”。

根据表单内部字段状态自动变色

核心 CSS

@supports selector(:has(*)) { .form-card:has(:invalid) { border-color: oklch(75% 0.14 25); } .form-card:not(:has(:invalid)):has(:valid) { border-color: oklch(72% 0.12 145); } }

提示：`:valid`/`:invalid` 与 `required`、`type=email`、`pattern` 等原生校验配合使用很舒服。

示例 3：hover / focus 联动父级（`:has(a:hover)` / `:has(a:focus-visible)`）

这类写法可以把“子项被交互 → 父级出现提示/边框/阴影”的逻辑全部交给 CSS。

  • 账号设置Tab / Hover
  • 通知偏好Tab / Hover
  • 安全中心Tab / Hover

核心 CSS

@supports selector(:has(*)) { .menu:has(a:hover), .menu:has(a:focus-visible) { border-color: oklch(78% 0.06 250); } }

小技巧：`:focus-visible` 比 `:focus` 更贴近可访问性体验（键盘导航时才显著）。

示例 5：组合选择与约束（`:has()` + 其它选择器）

`:has()` 经常会与 `:not()`、子代选择器 `>`、属性选择器等组合，形成“更精确的条件”。

这张图当前“描述完整”。点击按钮模拟“缺少描述”。

核心 CSS（组合条件）

@supports selector(:has(*)) { /* 当 figure 里存在一个“缺少描述标记”的图片时，强调 figure */ .figure:has(img[data-alt="missing"]) { border-color: oklch(78% 0.1 25); } }
关于“缺少 alt”的说明
严格意义上 CSS 不能直接判断 `alt` 为空/缺失的语义质量；本例用 `data-alt` 来模拟“质量问题”。生产中更推荐在构建/渲染阶段保证可访问性。

最佳实践与降级（建议直接抄用）

推荐写法：用 `@supports selector(:has(*))` 包起来
把 `:has()` 当作“增强层”。旧浏览器走基础样式，新浏览器自动获得更强交互。
/* 基础样式：所有浏览器都有 */ .row { border: 1px solid #ddd; } /* 增强样式：仅在支持 :has() 时启用 */ @supports selector(:has(*)) { .row:has(input:checked) { border-color: #2ecc71; } }
降级方案：极少数场景可用 JS 补一个 class
如果你必须支持不含 `:has()` 的浏览器，可以在 `@supports not selector(:has(*))` 分支里用 JS 监听并给父元素加/删 class。
if (!CSS.supports("selector(:has(*))")) { document.querySelectorAll(".row").forEach((row) => { const cb = row.querySelector("input[type=checkbox]"); const sync = () => row.classList.toggle("is-checked", !!cb?.checked); cb?.addEventListener("change", sync); sync(); }); }
性能与可维护性提醒
- `:has()` 的匹配成本通常高于普通选择器，尽量把范围限制在组件根节点（例如 `.card:has(...)`），避免在 `body:has(...)` 这种大范围上做复杂条件。
- 条件越精确越好：优先用直接子代 `:has(> ...)`，少用深层后代 `:has(.a .b .c)`。
- 把它当作“状态联动”的工具：表单校验、行选中、局部 hover/focus 指示、含特定子组件的布局变化。
